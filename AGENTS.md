# Camua UI package

- Git origin is https://github.com/shulkme/camuaui.git; only this library belongs to that repository. Commit/push source before publishing. publish.yml checks all pushes/PRs and publishes only missing stable camuaui versions from main via npm OIDC, verifying registry checksums. Never publish from PRs or overwrite existing versions. The stable create-camuaui launcher is bootstrapped once and is not republished with core releases; see docs/releasing.md. npm run release requires clean main and pushes the checked version commit. No credentials or generated artifacts in Git.

- npm may process a successful publish for several minutes. Verify the exact version through fresh metadata and tarball URLs (query parameters also bypass cached initial 404s), retry transient network/404/429/5xx failures for up to five minutes, and compare both metadata and downloaded archive digests. Fail immediately on identity/checksum/permission errors. A verification timeout is pending publication visibility, not a failed upload. Workflow reruns verify existing releases without republishing or changing their versions.

- npm packages ship compiled/minified CLI ESM in dist/ plus the intentionally uncompiled React registry. bin/ only bootstraps dist/. Never ship src/, scripts/, test/ or source maps. esbuild chunks must stay directly inside dist/ so packageRoot/registryRoot based on import.meta.url resolve correctly. Build before tests that execute bin/. Keep third-party runtime packages external and declared. Source remains in Git.

- create-camuaui is a stable npm create launcher using npm exec --prefer-online --package=camuaui@latest to run the core's create-camuaui bin alias. Do not pin camuaui as its dependency or synchronize its independent version. scripts/build-create.mjs copies its license only. Publish a core with the bin alias before bootstrapping the launcher. The core creator uses official @latest Next/Vite scaffolds, requires empty targets, then installs UI and replaces only fresh starter entry/page/CSS to wire UIProvider and preview. Existing React projects auto-detect and use the unchanged installer without replacing routes, pages or Provider. Dry-run must not execute scaffolds, install or write. Never delete partial scaffold output on failure. Test new TS/JS projects and existing-project preservation.

- Modal/Dialog share modalMotionClasses driven by Base UI data-nested-dialog-open and --nested-dialogs: each descendant scales the parent down by 4% and moves it up 12px, capped at 3 levels. Keep each nested Backdrop visible with forceRender and fixed viewport coverage, between the parent and child popups. Preserve starting/ending style priority, reduced-motion handling, viewport centering and Base UI focus/dismissal behavior. Do not count dialogs with document observers or transform the viewport/portal.

- List is a semantic ul/li composition with ListItemMedia, ListItemMeta (alias ListItemContent), ListItemTitle, ListItemDescription and ListItemActions. Defaults match the reference: divided=true, hoverable=false, size=md; sm/md/lg adjust row spacing, not Avatar size. Rows can override divided/hoverable. Use divider/background-hover and stable row padding; retain independent keyboard-accessible row entry and action buttons. No automatic li click handlers or nested buttons.

- Empty is a presentation-only composition: Empty, EmptyHeader, EmptyIcon, EmptyTitle, EmptyDescription, EmptyActions and EmptyExtra. Keep a flat 16px surface card, 48px rounded-lg surface-muted icon tile (24px SVG), semibold title and optional text/actions. Extra has no divider or top padding; -mt-3 reduces the default 24px parent gap to 12px. Use existing theme tokens, React 18/19 refs and className overrides, without loading/routing behavior or new dependencies. Demonstrate onboarding and filtered results; list empty states stay inside semantic ListItem wrappers.

- PageStack is a framework-independent controlled content switcher; PageStackPage values are unique and ordered parent to child. Preserve mounted state, inert/aria-hidden inactive pages, focus transfer only from departing content, initial SSR layout, dynamic height measurement, reversible CSS translate transitions and reduced-motion support. Keep padding inside pages. No menu semantics, routing dependency or global key handlers.

- Use Camua UI as the independent library name. Keep preview copy generic, without Camua product branding or marketing slogans. The Card background demo wrapper uses rounded-lg (8px); Card itself stays rounded-2xl (16px). Tabs use secondary text when inactive and primary text on enabled hover/active; disabled text stays quaternary.
- This project ships a Node ESM CLI and a local React source registry. Components must not import Next.js, Vite, Remix, project aliases, or application-specific modules.
- CLI presentation lives in src/reporter.js: cyan steps/prompts, green success, yellow warnings, red errors and dim details. Respect TTY, NO_COLOR and FORCE_COLOR; version/list stay plain text. Preserve package-manager logs and exit status; never suppress supply-chain checks or migrate unrelated consumer dependencies to hide warnings. README is written for package consumers, without unpublished/local-tarball instructions.
- The local Vite preview lives in test/ and imports registry source directly. npm run dev serves it on port 3001; port 3000 belongs to another program and must not be used. Keep the entire test/ directory out of the published npm package.
- Keep the supplied palettes and established visuals. UI uses Base UI and Tailwind 4; copy components into consumers rather than making them depend on this package at runtime.
- Support React 18/19 refs using forwardRef at styled component boundaries. Preserve generic values and SSR-safe markup. Keep "use client" on interactive modules.
- CLI defaults to synchronizing all components and their required helpers/styles. Optional DesignSystem examples are installed only when chosen; never create framework routes.
- Updates overwrite owned source files with a backup. Preserve unrelated project code, CSS rules, scripts and PostCSS plugins. Validate paths and symlinks before writes; don't execute project config files while inspecting them.
- Missing dependencies are requested with @latest using the project's package manager. Leave existing compatible dependencies intact; fail clearly for unsupported Tailwind 3 or React <18.
- Read README.md for the public interface. Tests use node:test. Run npm run check, npm test and npm pack. Verify actual generated projects and the packed CLI as well as direct local execution.
- Card uses rounded-2xl (16px). Menu/Select popup radii/padding are 8px/4px; items are 4px with px-2. Modal/Dialog/Drawer/Toast keep 24px radii. Button, Input, InputOTP, Select, Combobox, Autocomplete, InputNumber, Segmented support sm/md/lg = 32/36/40px, default md. Button padding stays 14/18/22px, font-normal, and onlyIcon makes matching square buttons. Segmented item heights are 28/32/36px plus 2px track padding. InputNumber inner input/step heights are 22/26/30px with 4px group padding, 1px border and 3px inner radii. Switch supports sm (28x16px, 12px thumb/travel) and default md (36x20px, 16px thumb/travel). Other components, including Tabs/Slider and Checkbox/Radio, keep their existing dimensions and gain no size prop.
- Modal footer buttons default to md via ModalFooter/DialogFooter/DrawerFooter and the DrawerContent footer slot. Explicit Button size overrides the footer default; regular buttons also default to md. Switch unchecked track uses bg-surface-hover, matching Slider tracks; its enabled hover mixes in 8% primary, and the checked track stays accent-700.
- Neutral component borders share control-border: gray-200 (#e8e8e8) in light, primary at 14% alpha in explicit/system dark. Hover uses control-border-hover: gray-300 in light, primary at 18% alpha in explicit/system dark. Keep 1px width; hover must not override focus, selected, invalid or disabled states. Switch/Segmented/Slider also provide subtle enabled hover feedback.
- Register custom Tailwind font sizes and shadow sizes in utils. shadow-none must override shadow-popup. Keep light/system/explicit dark theme behavior aligned.

- Shared icons use a 24px viewBox with strokeWidth 1.5, round line caps and joins. Select arrows rotate 180 degrees while open, with reduced-motion support.
- Optional Menu examples have their own card/file covering grouping, nested submenus, radio/checkbox, hover, close behavior, links/dialogs, detached/controlled triggers, arrows/animations and filtering. Preserve MenuSub/Trigger/Content and filtering wrappers when updating registry sources.
- MenuContent with a header has no popup padding; its List supplies the 4px padding. MenuInput sits flush at the popup's top and sides with 8px top corners and square bottom corners. MenuInput and ComboboxSearchInput share a 36px search header, a search icon, bottom separator only and a 2px accent focus outline inset 3px (leaving 1px clearance to the popup edge), without accent on the separator. Keep focus rings visible and the list independently scrollable.

- Combobox retains the Base UI Root Value/Multiple/Item generics. Its Input belongs inside InputGroup; search-in-popup uses ComboboxSearchInput in Content.header. Optional examples cover all 9 official example topics, including async requests with cleanup and a 10,000-row virtual list. CLI installs @tanstack/react-virtual only when examples are enabled; core Combobox has no virtualizer dependency.

- ComboboxInputGroup uses 3px content padding and 8px trailing action padding plus a 1px border: 24/28/32px chips have equal 4px outer gaps and 4px radii concentric with the 8px group for the 32/36/40px controls. Input-style triggers keep a flexible value slot and a centered trailing icon, including empty/placeholder states.

- DesignSystem section order is colors, typography, geometry, buttons, then components. Component group cards occupy full-width single rows; form controls (including sliders and Segmented) and Combobox examples belong to the form group. Modal and Dialog share the Tooltip/Popover/Toast card. Drawer keeps only its comprehensive standalone examples. Inner scenario comparison grids may remain responsive.

- Combobox arrows have transparent hover backgrounds and a consistent 13px glyph inset from the outside right edge in icon/input trigger modes, with/without Clear or Chips. Icon trigger hit areas stay 24px and center their glyph; do not put ml-auto on the icon inside the icon button. Clear and ChipRemove keep their own hover feedback.

- Geometry preview radius examples share equal-size surface-muted tiles (including rounded-full); use equal-height grid rows. All neutral preview borders use control-border.

- Danger Button uses only the four currently needed danger background/hover/active/foreground semantic tokens: solid error-700 mixed with 12%/20%/28% black for default/hover/active, with white text in all themes. Keep disabled styles dominant and base palettes intact. Combobox arrow rotation uses its parent trigger data-popup-open state, since BaseCombobox.Icon has no open state of its own.

- Size is inherited through Select/Combobox/InputNumber roots and Segmented to their styled parts. Group/Trigger size overrides are local and explicit; DOM wrappers continue forwarding refs and state className/render. Input size is a visual enum (omit the native numeric size). Popup search headers remain 36px. ControlSizeExamples in size-examples.tsx demonstrate all requested sizes, with the md rows omitting the prop to verify defaults.
- ComboboxChip uses leading-none so short Chinese/Latin labels align with the centered remove icon instead of inheriting body line-height. Preserve 24/28/32px chip heights, 4px outer gaps and the remove icon position.

- Public naming: Modal wraps Base UI Dialog for general content/editing; Dialog wraps Base UI AlertDialog for confirmations, with no close icon by default. DialogCancel/Action compose Button with render; overlay click must not dismiss confirmations. Existing generic dialog examples use Modal; Drawer draft confirmation uses Dialog. Document this breaking import/behavior migration.
- InputOTP wraps Base UI OTPField with default 6 slots, sm/md/lg square slots 32/36/40px, optional groups/separators, paste/normalization/mask/form integration. Autocomplete wraps Base UI Autocomplete for free text, preserves grouped/flat item inference and has the same three sizes and neutral outlines as Combobox. ScrollArea uses Base UI primitives with 10px tracks, 2px padding and 6px primary/20 thumbs, no new theme tokens. Add examples to the single-row form grouping and a separate ScrollArea card.

- ScrollArea scrollbars fade in on root hover (Base UI data-hovering) and keyboard focus-visible, then fade out on leave. variant="fade" uses the official viewport overflow-distance mask (up to 40px) for each scroll axis; avoid overlays that intercept content or extra JS scroll listeners. Preserve 6px thumbs and reduced-motion behavior.

- Modal/Dialog center their relative Popups through a fixed Base UI Viewport grid. Do not restore persistent translate(-50%, -50%) positioning; it can create hover edge artifacts on nested buttons. Keep footer buttons identical to ordinary Button styling, without extra shadows, borders or hover transforms; retain popup enter/exit animation and keyboard focus.

- Avatar has one size, 40x40px, with no size prop. Shape is circle (default rounded-full) or square (rounded-lg, 8px). All shapes use a 1px border-control-border border included in the 40px outer size. Root and fallback use leading-none with flex centering for Chinese/Latin text. Preserve image/fallback clipping, caller className overrides, render and refs; show both shapes in the Avatar card, not the multi-size control examples.

- Enabled Menu/Select/Combobox/Autocomplete items use cursor-pointer via itemClasses; keep disabled items non-interactive. Large-overlay close buttons (Modal/Dialog/Drawer/Toast) display 20px icons within the existing 32px hit area, while input clear/chip icons remain 16px.

- ContextMenu wraps Base UI ContextMenu Root/Trigger/Positioner; preserve pointer positioning and long-press handling rather than implementing custom document events. Reuse styled Menu items/groups/selection/submenu triggers because Base UI shares those primitives. ContextMenuContent uses the same 8px popup/4px padding/item styling and motion. Follow official basic, Using with Menu and Nested menu examples; keep visible Menu actions as an alternative to right-click, and include radio/checkbox selection.

- MenuItem/MenuLinkItem and their ContextMenu aliases share variant="default" | "danger". Danger uses text-error-800 (one palette step lighter than error-900 in light mode) and data-highlighted:bg-error-700/10 for both pointer and keyboard feedback. Disabled text remains quaternary. Use the variant in examples rather than ad hoc red text classes; do not add danger menu theme variables.

- Divider and lightweight page hover use exactly two additional semantic variables: --divider mixes control-border at 60% with transparent; --background-hover mixes background and surface-muted equally. Register divider/background-hover Tailwind colors. Use divider for separators (including Menu/ContextMenu, Autocomplete and popup search headers); preserve actual control outlines. The optional conversation list demonstrates 40px avatars, name/description, visible action menus, internal dividers, lightweight hover, selected surface-muted, keyboard access, reorder and removal, in one full-width example card.

- Keep theme.css free of explanatory comments; use blank lines to separate palette/semantic groups and keep rationale in docs.

- Dark content surfaces (Card / bg-surface) use gray-200 (#181818) above the gray-50 page (#070707); secondary components and raised popups remain gray-300 (#262626). Update both explicit and system dark mappings together, without borders/shadows on cards or new theme tokens. Light content surfaces remain white.

- The DesignSystem theme Segmented floats at the top of the viewport while scrolling. Keep its fixed wrapper below popup/modal layers, use pointer-events-none on the positioning band and pointer-events-auto on the control, and reserve header space on narrow screens so it does not cover the page title.

- Theme changes are immediate: UIProvider observes root data-theme changes and system color-scheme changes when following the system, and cancels only CSS color/fill/stroke/shadow transitions before paint. Preserve normal hover transitions, keyframes, geometry/opacity motion and host-owned theme state. Disconnect observers/listeners on unmount; avoid globally disabling all animations or adding theme timers/variables.
